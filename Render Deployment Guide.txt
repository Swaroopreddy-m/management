# Render Deployment & Verification Guide: Hierarchical Multi-Organization Management

This guide provides step-by-step instructions to deploy the hierarchical multi-organization management system on Render, completely isolated from any previous deployments.

---

## Step 1: Deploy a Dedicated PostgreSQL Database on Render

1. Log into your [Render Dashboard](https://dashboard.render.com).
2. Click **New +** and select **PostgreSQL**.
3. Configure the database details:
   - **Name**: `management-hierarchy-db`
   - **Database Name**: `employee_db`
   - **User**: `postgres` (or auto-generated)
   - **Region**: Choose your nearest region (e.g., Oregon US-West or Frankfurt EU).
4. Click **Create Database**.
5. Once provisioned, copy the **Internal Database URL** (e.g. `jdbc:postgresql://management-hierarchy-db:5432/employee_db`).

---

## Step 2: Database Schema & Automated Seeding

The application automatically checks and provisions all hierarchical tables and initial seed data on startup via `DataInitializer.java`.
Alternatively, you may run [schema.sql](file:///c:/Users/user/Documents/Projects/employee-management/schema.sql) manually via `psql` or DBeaver using the External Database URL:
- Super Entities: `SE001` (Global Enterprise Group)
- Super Admins: `SA001` (Enterprise Super Admin)
- Organizations: `ORG001` (Apex Solutions), `ORG002` (Beta Industries)
- Organizational Entities: `BR001` (Apex HQ), `BR002` (Apex West Coast), `DEPT001`, `STR001`, `BR003`
- Page Registry: `DASHBOARD`, `EMPLOYEE_MANAGEMENT`, `USER_MANAGEMENT`, `BRANCH_MANAGEMENT`, `DEPARTMENT_MANAGEMENT`, `STORE_MANAGEMENT`, `REPORTS`, `SETTINGS`, `DYNAMIC_PAGES`
- Permission Groups & Org Approvals for `ORG001`
- Seed users: `developer` (dev123), `superadmin` (admin123), `US001` (password123)

---

## Step 3: Deploy Web Service on Render

1. On the Render Dashboard, click **New +** and select **Web Service**.
2. Connect the target repository: `Swaroopreddy-m/management` (or `employee-management`).
3. Set **Branch**: `feature/hierarchy-permissions`.
4. Configure service parameters:
   - **Name**: `management-service`
   - **Environment**: `Java` (or `Docker` via repository `Dockerfile`)
   - **Build Command**: `./mvnw clean package -DskipTests`
   - **Start Command**: `java -jar target/employee-0.0.1-SNAPSHOT.jar`
5. Configure **Environment Variables**:
   - `PORT`: `8080`
   - `SPRING_DATASOURCE_URL`: `jdbc:postgresql://<RENDER_INTERNAL_HOST>:5432/employee_db`
   - `SPRING_DATASOURCE_USERNAME`: `<RENDER_DB_USER>`
   - `SPRING_DATASOURCE_PASSWORD`: `<RENDER_DB_PASSWORD>`
6. Click **Create Web Service**.

---

## Step 4: Online Endpoints & Workflow Verification

Once live (e.g. at `https://management-service.onrender.com`), verify:

### 1. Interactive Portal Web UI
Open your browser and navigate to:
`https://management-service.onrender.com/portal`
- Use the **Active Role Context** dropdown to test Developer, Super Admin, Org Admin, and Staff User perspectives live.
- Observe how the **Dynamic Navigation Bar** updates dynamically based on effective permissions!

### 2. Authentication & Effective Permission Calculation
```bash
curl -X POST https://management-service.onrender.com/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"userId": "US001", "password": "password123"}'
```
Expected response:
```json
{
  "status": "LOGIN_SUCCESS",
  "userId": "US001",
  "role": "ORG_ADMIN",
  "organizationId": "ORG001",
  "permissions": { ... }
}
```

### 3. Dynamic Navigation Endpoint
```bash
curl -X GET https://management-service.onrender.com/api/navigation \
  -H "X-User-Id: US001" \
  -H "X-Organization-Id: ORG001"
```

### 4. Developer Dynamic Page Registry
```bash
curl -X GET https://management-service.onrender.com/api/developer/pages
```

### 5. Super Admin Organization Management & Access Requests
```bash
# List organizations
curl -X GET https://management-service.onrender.com/api/super-admin/organizations

# List pending access requests
curl -X GET https://management-service.onrender.com/api/super-admin/requests?status=PENDING
```

### 6. Org Admin Console & Group Permissions
```bash
# List pages approved by Super Admin for ORG001
curl -X GET https://management-service.onrender.com/api/org-admin/approved-pages \
  -H "X-Organization-Id: ORG001"

# List branches, departments, stores
curl -X GET https://management-service.onrender.com/api/org-admin/entities \
  -H "X-Organization-Id: ORG001"
```

### 7. Scoped Employee CRUD & Entity Enforcement
```bash
# List employees in ORG001
curl -X GET https://management-service.onrender.com/api/employees?organizationId=ORG001 \
  -H "X-User-Id: US001" \
  -H "X-Organization-Id: ORG001"
```

- `https://management-service.onrender.com/page/confirm`
- `https://management-service.onrender.com/page/acknowledge`
